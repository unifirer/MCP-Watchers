PLAN: VAD watcher stack memory/CPU leak fixes
Date: 2026-09-06
Author: ZCode session (investigation + approved plan)

BACKGROUND (measured evidence)
- PID 209416 graphify-watch-wrapper.ps1: 4.3 GB, 65 threads, 34,505 CPU-s
  over ~8 h (avg ~1.2 cores). Last real work 19:44 the prior evening.
- PID 162592 tail_graphify-rs.ps1: 4.25 GB, 44 threads (still climbing at
  death), 10,438 CPU-s (avg ~0.36 core).
- Fresh instances of the same scripts: threads already 33/37 at 5 min,
  tailer private memory 129 -> 155 MB in 30 min. Zero FS events measured
  in a 20 s quiet window while both still burned CPU.
- Stack restart at 02:04 was the launcher teardown + relaunch, not a crash.

ROOT CAUSES
1. dev_tools/graphify-watch-wrapper.ps1
   - $pending Queue[string] grows unbounded: every FS event restarts the
     1500 ms debounce timer, so sustained churn never flushes. Rebuild
     cascades enqueue the same path thousands of times (chunk writes).
   - Flush spawns one `git check-ignore` subprocess per path
     (Modules/graphify_ignore_gate.ps1:52).
   - Parent-liveness Get-Process poll every 1 s.
2. Pane tailers (generated by launcher template, New-WatcherPaneScript,
   launcher lines 2474-3100; all four panes share one template)
   - Full-log Get-Content every 500 ms tick (deployed line 510) =>
     constant large-array churn, LOH pressure.
   - $global:recentChanges hashtable never pruned (deployed line 129/158).

FIXES
1. NEW Modules/watcher_log_tail.ps1: Read-WatcherLogTail -Path -Offset
   -BacklogBytes. Byte-offset incremental read; partial trailing line held
   back; rotation/shrink resets to backlog; UTF-8 + BOM handled.
2. Launcher template: dot-source the new module via new __PARENTDIR__
   token; replace whole-file reads with Read-WatcherLogTail; prune
   $global:recentChanges at 500 entries (evict oldest); remove obsolete
   Get-CompleteLineCount.
3. Modules/graphify_ignore_gate.ps1: add Test-PathsIgnoredByGraphify
   (one `git check-ignore --stdin` per flush; falls back to per-path).
4. dev_tools/graphify-watch-wrapper.ps1: $pending -> ordered Dictionary
   (dedupe); dot-dir + $safe filter at enqueue; staleness flush at 30 s;
   hard cap 5000 entries; extract testable Invoke-GraphifyPendingFlush;
   parent check every 5 s.
5. Tests (Pester 3.4.0, run per-file):
   - tests/graphify_watch_wrapper.tests.ps1: dedupe, staleness flush,
     enqueue filter.
   - tests/graphify_ignore_gate.tests.ps1: batch == per-path parity.
   - tests/watcher_log_tail.tests.ps1 (NEW): offset advance, partial
     line hold-back, rotation reset, BOM.
6. Post: changelog, automem store, commit, close beads.
7. Activate: restart watcher stack (user approved), touch a file to
   confirm rebuild, then 30-min sampler on the new pair: flat memory,
   threads near baseline, near-zero idle CPU.

CONSTRAINTS
- Launcher template is a single-quoted here-string (lines 2497-3096):
  purely textual edits, keep __TOKEN__ names and the '@ terminator.
- Deployed pane scripts are overwritten on every launch (no staleness
  check): template is the single source of truth.
- Teardown is PID-scoped (Modules/watcher_teardown.ps1): restarting
  panes is safe.
