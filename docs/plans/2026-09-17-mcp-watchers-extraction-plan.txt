6. MULTI-REPO PATCH - REQUIRED BY DECISION D4

  The operator wants to copy a shortcut of the launcher into other repos and
  use one tool for all of them. The launcher does not support that today.
  Four behaviours block it. All four are in the launcher, not in the modules.

  6.1 The launcher forces the working directory (BLOCKER)
      Lines 6 to 8:
        if ($scriptDir) { Set-Location -LiteralPath $scriptDir }
      Effect: the CWD is always the folder that holds the .ps1.
      But the Windows Terminal panes open with `-d .` (lines 4002, 4009,
      4016, 4022). So the panes, the log paths, and every indexer resolve
      against the launcher folder, never against the caller's repo.
      Fix: remove the Set-Location, or gate it behind an explicit switch.
      Keep $scriptDir for locating Modules\. The two roles are different and
      must be split.

  6.2 The single-instance guard is global (BLOCKER)
      Line 49: $lockFile  = %LOCALAPPDATA%\watchers\###1-launcher.lock
      Line 75: $mutexName = 'Global\VAD_Watchers_Launcher'
      Effect: the guard is FIRST-WINS across the whole machine. A shortcut in
      repo B exits silently while repo A runs. This defeats D4 completely.
      Fix: derive a short workspace key from the resolved CWD, for example a
      SHA-256 prefix, and append it to both names:
        ###1-launcher-<key>.lock
        Global\VAD_Watchers_Launcher_<key>
      The key must be a stable function of the normalized absolute CWD.

  6.3 The process sweep is workspace-agnostic (BLOCKER)
      Modules\watcher_patterns.ps1 holds one shared list. The patterns match
      on command-line substrings only:
        powershell.exe + 'panes\tail_'
        powershell.exe + 'graphify-watch-wrapper'
        pwsh.exe       + 'vad-grepai-sup'
        grepai.exe     + 'watch'
        gm.exe         + 'watch'
        repowise.exe   + 'watch'
      Stop-PriorLauncherInstances runs this sweep at startup.
      Stop-AllWatchers runs it at exit.
      Effect: a launcher in repo B kills the watchers of repo A. Teardown in
      one repo tears down all repos.
      Fix: add a workspace token to every generated command line, and require
      that token in the pattern. The pane tailers already live under a
      per-workspace path (C:\Temp\vad-watchers\panes\tail_*.ps1), so the
      natural token is the workspace key from 6.2. Until this is fixed, run
      the tool in ONE repo at a time.

  6.4 The terminal window name is global
      Line 3806: $wtWindowName = "vadwatchers"
      Effect: two repos share one window name, so the pane grid collides.
      Fix: append the workspace key, or take a -WindowName parameter.

  6.5 Other global mutexes to review
      Line 191 : Global\VAD_Watchers_Takeover
      Line 1303: Global\VAD_Grepai_Heal
      Line 1727: Global\VAD_GmSemanticBuild_$BuildKey   (already keyed)

  Recommended sequence for the patch:
    Step 1  Split $scriptDir from $workspaceRoot. Add a $workspaceKey.
    Step 2  Key the lock file, the mutex, and the window name.
    Step 3  Add the workspace token to the sweep patterns and the generated
            command lines. This step is the risky one. It touches teardown,
            so a mistake leaves orphaned processes.
    Step 4  Set $env:VAD_WORKSPACE_ROOT to the resolved workspace root when
            it is unset, so downstream tools agree on the target.
    Step 5  Verify each step with a live run in a scratch repository before
            trusting it in VAD.

  Do not apply 6.1 without 6.2 and 6.3. Removing Set-Location alone would
  make two repos fight over one lock, one window, and one sweep list.

8. RISKS

  R1  Two live launcher instances fight over shared state. Stop the old one
      before the cutover. This becomes safe only after patch 6.2 and 6.3.
  R2  The sweep patterns are workspace-agnostic. Until patch 6.3, run the
      tool in one repo at a time. A second repo's launcher kills the first
      repo's watchers.
  R3  The Startup shortcut points at the old path. Repoint it in the same
      session as the cutover. Otherwise a reboot launches the old copy.
  R4  Pester 3.4.0 is missing. The Pester gate cannot run until it is
      installed. See section 5.
  R5  Removing Set-Location alone, without 6.2 and 6.3, creates a worse bug
      than the one it fixes. Apply the whole set, or none of it.
  R6  VAD commit hooks take 2 to 3 minutes. The Bash tool default timeout is
      120 seconds and reports a false failure. Use a long explicit timeout
      and confirm with the reflog, not the exit code. The new repo has no
      hook, so its commits are instant.
  R7  The new repo is not self-contained for the watchers themselves. The
      external tools stay installed. README.md lists them as prerequisites.
  R8  Generated state must not be committed. .gitignore covers logs\,
      temp\, teardown-state.json, .grepai\, .memdb\, and *-out\. It was
      written before the first commit.
  R9  git autocrlf is enabled. Git normalized line endings on add, so a
      fresh clone on Windows gets CRLF. The .bat file needs CRLF. The .ps1
      files tolerate either. Add a .gitattributes if you want this pinned.
